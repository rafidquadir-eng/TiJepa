## 0. Objective

Produce, in one autonomous run, a **reproducible, computational-only bioRxiv-ready preprint draft**
plus open-source code and released model weights for **TiJepa-0**:

**Working title:** *TiJepa: self-supervised video representations of innate immune activation,
with a dynamics-to-chromatin bridge toward trained immunity*

Author: **Rafid Quadir** (sole author). Affiliation placeholder: *Immunome AI Biotechnologies,
New York, NY* — mark as `TODO(author): confirm affiliation`.

There is **no wet lab** and **no public imaging dataset of trained or tolerant innate cells**
(see the landscape report). The preprint therefore has three parts, all on existing public data:

| Part | Question | Pairing type |
|---|---|---|
| **A. Video SSL** | Does JEPA-style self-supervised video pretraining on open innate-immune microscopy capture activation / polarization state and support cell tracking? | Real labels (condition-level) |
| **B. Dynamics → chromatin** | Can single-cell NF-κB signalling dynamics (derived from live imaging) predict the transcriptional / chromatin state of **LPS tolerance**? | Real pairing, same lab, same conditions |
| **C. Bridge to trained immunity** | Where do β-glucan-trained and LPS-tolerant states fall on activation axes shared by omics and the learned image space? | Condition-level anchors across studies — **hypothesis only** |

### Deliverables (all in this repo, on branch `tijepa-v0`, opened as a PR)

1. `src/tijepa/` — installable Python package with all code.
2. `scripts/` — one command per stage, plus `scripts/run_all.sh`.
3. `results/` — every metric as machine-readable JSON/CSV, produced by code.
4. `figures/` — all preprint figures (PNG + PDF/SVG), produced by code.
5. `paper/` — preprint draft (`paper/tijepa.md` and, if a toolchain is available, `paper/tijepa.pdf`).
6. `reports/RUN_REPORT.md` — what ran, on what compute, what failed, all deviations.
7. Model weights: if ≤ 2 GB, attach to a GitHub Release `tijepa-0-v0.1` (draft release);
   otherwise write `reports/WEIGHTS.md` with exact instructions for the author to upload to
   Zenodo/Hugging Face. **Never commit weights to git.**

## 1. Rules (non-negotiable)

### 1.1 Scientific integrity
1. **No fabricated results.** Every number, table, and figure in `paper/` must be generated by code
   in this repo from data actually downloaded in this run, and must trace to a file in `results/`.
   Numbers in the manuscript are filled by `scripts/make_paper_numbers.py` from `results/*.json` —
   never typed by hand.
2. **No synthetic or simulated data presented as real.** Synthetic data is allowed only inside
   `tests/` for unit tests and must be named `synthetic_*`.
3. **No fake pairings.** Images and omics from different studies are never presented as matched
   samples. Part C is explicitly a condition-level, cross-study, cross-species *bridge*, labelled
   as hypothesis-generating everywhere it appears (abstract, results, figure legends).
4. **Null and negative results are reported**, not dropped. If TiJepa does not beat a baseline,
   the paper says so.
5. **Leakage control.** All evaluation splits are grouped by the highest available biological /
   technical unit (batch > animal/donor > movie > field of view > cell). Never split at the
   cell or frame level when a higher grouping exists.
6. **Claims allowed:** "self-supervised video representations of innate immune *activation /
   polarization*", "signalling dynamics predict features of *LPS tolerance*", "projected position
   of trained/tolerant states (hypothesis)". **Claims not allowed:** that TiJepa or iMEMORY
   *identifies trained immunity from images*; any claim implying imaging of trained cells was
   performed; any claim about human disease, lupus, or patients.
7. **iMEMORY.** Do not access, request, or reference any private or partner data (Mount Sinai,
   Columbia, Broad, or iMEMORY patient data). The Discussion may say the learned representation is
   designed to be added to multi-omic models such as iMEMORY as future work — nothing more.

### 1.2 Licences
1. **Pretraining data:** only CC0, CC BY, or MIT/BSD licensed data (Section 4 lists them).
2. **Excluded entirely:** Zenodo `10.5281/zenodo.16319732` (CC BY-NC-ND), DeepCell
   DynamicNuclearNet, the Cellpose *training set*, CTMC-v1, LIVECell (licence unresolved),
   Cell Tracking Challenge data (no stated licence).
3. **Third-party model weights** (DINOv2, V-JEPA, Cellpose models, CoTracker, etc.): record the
   licence of each in `manifests/models.yaml`. Non-commercial weights are acceptable for this
   non-commercial preprint **only** if the paper's Methods states the licence. Prefer permissive.
4. Record every dataset's verified licence (read from the record itself, not from this plan) in
   `manifests/datasets.yaml`. If the record's licence differs from this plan, the record wins.
5. Repo licence: add `LICENSE` = **Apache-2.0** for code and `LICENSE-docs` = **CC BY 4.0** for
   text/figures. `TODO(author)` note in the PR if a non-commercial licence is preferred.

### 1.3 Repository hygiene
1. Work on branch `tijepa-v0`. Commit at each milestone (Section 9). Push regularly. Open one PR
   to `main` at the end. **Never** force-push, rewrite history, or push to `main` directly.
2. Raw data, caches, checkpoints, and large arrays stay out of git (`.gitignore` already covers
   `data/`, `checkpoints/`, `*.pt`, `*.tif`, `*.zarr/`, etc.). Keep all raw/processed data under
   `data/` and all checkpoints under `checkpoints/`. Committed result files must be < 5 MB each.
3. Put manifests in `manifests/` (not `data/`, which is gitignored).
4. Downloaded files are untrusted: extract archives into their own directory, never execute code
   shipped inside a dataset, run Python that reads them with `-I` where practical.

### 1.4 Authorship and disclosure
1. Sole author: Rafid Quadir. Do not invent co-authors, affiliations, funding, or acknowledgements.

## 5. Part A — Self-supervised video representation (TiJepa-0)

### A1. Preprocessing
1. **Spatial normalisation:** resample every dataset to a common **0.65 µm/px** (record per-dataset
   factors). If a dataset lacks pixel size metadata, use the value from its record/paper and log it.
2. **Detection & tracking:** segment cells (Cellpose `cyto3` pretrained model, licence recorded;
   or a classical phase/brightfield pipeline if Cellpose is unavailable) and link with a permissive
   tracker (`laptrack` or `trackpy`). For S-BIAD2196 use the provided masks/tracks.
3. **Clips:** cell-centred crops of **96×96 px** (≈62 µm), **16 frames**. Temporal resampling to
   reduce the 8 s vs 5 min mismatch: for ComplexEye sample frames with a random stride drawn so the
   effective interval spans ~1–5 min where movie length allows, and always include a stride-1 view.
   Record the effective-interval distribution per source.
4. **QC:** train a small classifier on S-BIAD2133 anomaly masks (any-anomaly vs clean, frame
   level); drop clips whose frames score above a threshold chosen on its validation split. Report
   the fraction removed per source.
5. Store clips as uint8 arrays in sharded files under `data/processed/` with an index CSV
   (source, movie, track_id, t0, stride, µm/px).

### A2. Model
- **T1/T2 (pixel-space video JEPA):** ViT-S encoder over spatio-temporal tubelets
  (2 frames × 8×8 px patches on 96×96 → 12×12×8 tokens), context encoder + EMA target encoder +
  narrow predictor, multi-block spatio-temporal masking (V-JEPA style: predict target-encoder
  latents of masked tubelets; L1 loss in latent space; no pixel reconstruction). Initialise the
  spatial patch embedding/blocks from DINOv2-S/14 when available (adapt patch size by
  interpolation or train the patch embed from scratch — record the choice).
- **T0 (feature-space JEPA):** frozen DINOv2-S/14 (fallback: ImageNet ViT-S) per-frame embeddings
  of each clip; a small temporal transformer predicts embeddings of masked frames from visible ones
  (EMA target over the same frozen features); the clip representation is the mean of the temporal
  transformer's output tokens. Name it honestly in the paper ("feature-space temporal JEPA").
- Optimiser AdamW, cosine schedule with warmup, bf16 where supported. Save checkpoints every
  ~10% of budget; resume-safe.

### A3. Training
- Train within the tier budget. Monitor for collapse (embedding std per dimension, effective rank);
  if collapse is detected, adjust (EMA, predictor depth, masking ratio) once and record.
- Save final weights to `checkpoints/tijepa0_<tier>.pt` and a config card.

### A4. Evaluation (frozen encoders; identical probes for every encoder)

**Encoders compared:** (E1) hand-crafted morphology + motility features; (E2) ImageNet ViT-S
frame-mean; (E3) DINOv2-S frame-mean; (E4) TiJepa-0; (E5) TiJepa-0 on **frame-shuffled** clips
(tests use of temporal order); (E6) TiJepa-0 random-init (architecture control).

Hand-crafted features (E1): area, perimeter, eccentricity, solidity, major/minor axis, mean/std
intensity, texture (Haralick on a fixed GLCM setting); motility: mean speed, persistence
(net/total displacement), MSD exponent α, turning-angle statistics, fraction of time moving.

**A4.1 BMDM M0/M1/M2 (Dryad m0cfxpp8v) — headline.**
- Unit: tracked cell (≥ 16 frames). Probe: logistic regression (L2, C tuned by inner CV) and a
  1-hidden-layer MLP; also a random forest for E1.
- Splits: **leave-one-batch-out** if batch IDs are recoverable; otherwise leave-one-movie-out
  (state this limitation prominently). Never mix cells of one movie across train/test.
- Metrics: balanced accuracy, macro-F1, one-vs-rest AUROC at **cell level** and **movie level**
  (mean of cell probabilities). 95% CIs by cluster bootstrap over movies (2,000 resamples);
  significance vs chance and vs E1 by permutation of movie labels (1,000 permutations) and paired
  bootstrap. Seeds 0/1/2 for learned encoders; report mean ± sd across seeds.
- Also report magnification as a confound: probe accuracy for predicting magnification/batch from
  embeddings (lower is better) and results stratified by magnification.

**A4.2 BBBC054.** Per-cell crops at annotated (x, y); 3-class probe with FOV-grouped CV; plus ridge
regression of LPS exposure time (h) from embeddings with FOV-grouped CV (Spearman ρ, MAE).

**A4.3 Point tracking (LTDB, Immunemap, held-out S-BIAD2196).** Given a query point at t₀, track it
for the rest of the sequence. Methods: (i) nearest-detection linking baseline, (ii) patch-feature
correlation tracking using each encoder's patch tokens (same tracker for all encoders),
(iii) an off-the-shelf point tracker (e.g. CoTracker) if weights are obtainable — record licence.
Metric: TAP-Vid-style ⟨δ⟩ (mean fraction within {1, 2, 4, 8, 16} µm), median track survival
length; per dataset. If time is short, run S-BIAD2196 + LTDB and mark Immunemap as future work.

**Acceptance for Part A:** results exist for A4.1 with all six encoders, three seeds, CIs. Whether
TiJepa wins or loses, report it.

## 6. Part B — Signalling dynamics → chromatin state in LPS tolerance

### B1. Data understanding
Inspect the Zenodo traces and the Tay-lab code. Produce `results/partB/conditions.csv` mapping
every condition (first ligand, second ligand, timing) to (a) number of cells with traces,
(b) GSM IDs in GSE260996 and GSE261647 if any. Identify the replicate/experiment unit for grouping.

### B2. Representations
- Hand-crafted trace features: baseline, peak amplitude and time, area under curve, number of
  peaks, oscillation period/power (FFT band), decay half-life, response to the second stimulus
  relative to the first.
- **Trace-JEPA:** 1D transformer over patches of the trace (e.g. 4-frame patches), masked-patch
  latent prediction with EMA target — the same JEPA principle as Part A. Self-supervised on all
  traces, excluding test groups when used for evaluation.
- Raw-trace MLP/1D-CNN supervised baseline.

### B3. Tasks
1. **Tolerance from dynamics (single cell):** naive→LPS vs LPS→LPS (and any other X→LPS available):
   predict prior exposure from the response to the second LPS stimulus. Grouped CV by experiment.
   Balanced accuracy, AUROC, CIs, seeds.
2. **Ligand identity:** first-ligand classification (6-class) for comparison with the published
   72.8% 4-class result (note the task difference explicitly; do not claim to beat it unless the
   task is identical).
3. **Dynamics → transcriptome / accessibility:** for conditions with both traces and RNA (and ATAC),
   regress condition-level expression of (a) the top 2,000 variable genes and (b) a tolerance gene
   set (B4) from condition-mean embeddings, ridge regression, **leave-one-condition-out**. Report
   per-gene Pearson r distribution and the number of genes with r > 0.5, versus a
   condition-label-permutation null (≥ 200 permutations). With few conditions this is
   underpowered — say so and report anyway.

### B4. Cross-species link to the human trained-immunity literature
- Mouse tolerance genes: LPS→LPS vs naive→LPS from GSE260996 (DESeq2-style via `pydeseq2`, or
  edgeR-equivalent; BH-FDR < 0.05, |log2FC| > 1).
- Human tolerance genes: LPS-tolerized vs RPMI from GSE58310; replicate in GSE172116 / GSE85243.
- Map via orthologs; hypergeometric overlap test (universe = genes measured in both); report
  odds ratio, p, and the overlapping genes. Report which of the overlapping genes are among those
  best predicted from dynamics in B3.

**Acceptance for Part B:** B1 and B3.1 complete with CIs; B3.3 and B4 complete or explicitly
explained.

## 7. Part C — Bridge to trained immunity (hypothesis-generating)

### C1. Human anchor signatures (GSE46903)
For LPS, IFN-γ and IL-4 vs baseline (matched time points): differential expression (limma-style
moderated t or Welch t + BH); take the top 100 up-regulated genes per stimulus as signatures
`S_LPS, S_IFNg, S_IL4`. Save gene lists.

### C2. Score trained / tolerant states
Rank-based single-sample scoring (implement a singscore-style score) of `S_*` in every sample of
GSE58310 (and GSE85243, GSE172116 for replication). Within each dataset, express scores relative to
that dataset's own unstimulated macrophage baseline. Output per-sample coordinates
(M1-like = mean of LPS/IFN-γ scores, M2-like = IL-4 score) for naive, β-glucan-trained,
LPS-tolerant, and macrophage baseline. Bootstrap over donors for CIs.

### C3. Image-side axes and projection
Using TiJepa-0 embeddings of Dryad BMDM cells (Part A): centroids `c_M0, c_M1, c_M2`. Map each omics
state's coordinates `(a, b)` (normalised so that the anchors land on their own centroids) to a
predicted embedding `ĉ = c_M0 + a·(c_M1 − c_M0) + b·(c_M2 − c_M0)`. Visualise: (i) the omics
coordinate plot; (ii) the image embedding (PCA/UMAP fitted on real cells) with predicted positions
overlaid with bootstrap uncertainty; (iii) the k = 9 real cells nearest each predicted position as
**illustrative exemplars, explicitly labelled "nearest observed cells to a predicted position — not
images of trained cells"**.

### C4. Limitations to state in the paper (verbatim intent, wording may vary)
Anchors are only three conditions, so the bridge is a low-dimensional linear interpolation; image
data are mouse BMDM while trained-immunity omics are human monocyte-derived; pairing is at the
condition level across studies and platforms (arrays vs RNA-seq); the predictions require a
prime–rest–restimulate imaging experiment to test, which the paper describes as future work.

**Acceptance for Part C:** C1–C3 complete with figures; every figure legend and the abstract carry
the hypothesis framing.

Cluster bootstrap CIs (2,000 resamples) at the grouping unit; permutation tests for "better than
chance"; paired bootstrap for encoder comparisons; BH correction where multiple comparisons are
made; report effect sizes, not just p-values. Seeds 0/1/2 for every learned model.

### 8.2 Figures (generated by `src/tijepa/viz/`, saved to `figures/`)

## 9. Execution order, milestones, and time budget

| # | Milestone | Commit message prefix | Wall-clock guide |
|---|---|---|---|

Run long downloads and training in the background and work on other milestones meanwhile. Commit
and push after each milestone so partial progress is never lost.

**Stop / degrade rules (never stall, never fake):**
- A dataset unavailable → mark it, continue, document in RUN_REPORT and MANUAL_DOWNLOADS.
- Training over budget → stop at the last checkpoint, evaluate that, document.
- An analysis impossible as specified (e.g. no batch IDs, too few conditions) → do the closest
  valid version, state the change in Methods and RUN_REPORT.
- Any step that would require private data, paid access, account creation, or bypassing an
  access control → skip and document for the author.

## Appendix — Known risks

| Risk | Mitigation |
|---|---|
| Large Zenodo archives too big for disk/time | Tier caps; smallest ZIPs first; range-read extraction for PhagoStat |
| 8 s vs 5 min frame-interval mismatch between pretraining and evaluation | Stride augmentation; report frame-shuffle control; discuss as limitation |
| Dryad BMDM has only 18 movies / 5 batches | Cluster bootstrap, leave-one-batch-out, permutation tests; frame as small benchmark |
| Batch/magnification confounds in BMDM data | Confound probes; stratified results |
| Tay condition ↔ RNA sample mapping ambiguous | Audit table in `results/partB/conditions.csv`; restrict to unambiguous conditions |
| Cross-species, cross-platform bridge in Part C | Rank-based scores; within-dataset normalisation; hypothesis framing |
| Third-party weight licences | `manifests/models.yaml`; state in Methods |
| Hallucinated references | Only resolved DOIs/PMIDs; otherwise `TODO(verify)` |
